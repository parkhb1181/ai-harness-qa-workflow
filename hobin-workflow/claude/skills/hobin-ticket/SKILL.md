# hobin 티켓 작성

목표: **워커가 사람에게 묻지 않고 끝까지 할 수 있고, 다른 티켓과 겹치지 않는 티켓.**

## 절차
1. 요청 원문을 그대로 보관한다. Jira 이슈라면 Jira 연결 도구로 요약, 설명, 인수 조건, 연결 이슈를 읽는다.
2. 저장소 구조를 가볍게 훑어 **수정 가능 경로**를 정한다 (`Glob`, `Grep`). 넓게 잡지 말고 필요한 폴더와 파일만.
3. 애매한 점은 한 번에 하나씩, 추천 답과 함께 묻는다. 추측으로 채우지 않는다.
4. 아래 기준으로 쪼갠다.
5. `hobin new`로 등록한다. 등록 직후 상태는 "작성 중"이다. **승인(`hobin ready`)은 사람이 확인한 뒤에만.**

## 쪼개는 기준
- 한 티켓은 **한 워커가 한 번에 끝낼 수 있는 크기**. 완료 기준이 7개를 넘으면 쪼갠다.
- **수정 가능 경로가 겹치는 티켓은 동시에 실행되지 않는다.** 병렬로 하고 싶으면 경로가 겹치지 않게 나눈다.
- 여러 티켓이 같은 인터페이스(API 형식, 데이터 구조)를 쓰면 **인터페이스를 정하는 티켓을 먼저** 만들고, 나머지는 `--depends`로 그 티켓을 선행으로 둔다. (계약 먼저)
- 화면과 API를 함께 바꿔야 하는 작은 기능은 억지로 나누지 말고 한 티켓으로 둔다.

## 좋은 완료 기준
- 실행해서 pass/fail을 가릴 수 있어야 한다.
  - 나쁜 예: "로그인이 잘 된다"
  - 좋은 예: "잘못된 비밀번호 입력 시 '비밀번호가 올바르지 않습니다' 문구가 보인다 (`npm test -- login` 통과)"
- "깨지면 안 되는 것"도 넣는다. 예: "기존 /api/v1/login 응답 형식은 그대로다"

## 등록 명령

**셸 명령에 요청 원문을 직접 끼워 넣지 않는다.** 원문에 `$(...)`나 따옴표, 줄바꿈이 있으면 셸이 실행해 버린다.
모든 필드를 **한 줄짜리 JSON**으로 만들어 표준 입력으로 넘긴다. JSON 안의 줄바꿈은 `\n`으로 쓴다.

```bash
hobin new --json - <<'HOBIN_JSON'
{"title": "로그인 오류 문구 개선", "source": "jira:WEB-123", "requested_by": "홍길동", "paths": ["src/auth/", "tests/auth/"], "depends": ["T-003"], "goal": "잘못된 로그인 시 원인별로 다른 문구를 보여 준다", "exclude": ["로그인 API 응답 형식"], "decision": ["문구는 기획서 v2 기준"], "eval": ["잘못된 비밀번호 입력 시 '비밀번호가 올바르지 않습니다'가 보인다", "없는 계정 입력 시 '가입되지 않은 이메일입니다'가 보인다", "npm test -- auth 통과"], "request": "요청자가 쓴 원문을 수정하지 않고 그대로. 줄바꿈은 \\n으로"}
HOBIN_JSON
```

- JSON은 반드시 **한 줄**이어야 한다. 그래야 원문 안에 어떤 줄이 있어도 heredoc이 끝나지 않는다.
- 수정 가능 경로는 고정된 폴더나 파일로 시작해야 한다 (`src/auth/`는 되고 `**/*.ts`는 안 됨).

## Jira 항목 대응
| Jira | hobin |
|---|---|
| 요약 | 제목 |
| 설명 | `--request` 원문, `--goal` |
| 인수 조건 | `--eval` 각 항목 |
| 연결 이슈 (Blocked by) | `--depends` (해당 hobin 티켓 ID) |
| 이슈 키 | `--source "jira:키"` |
| 보고자 | `--by` |

Jira에 인수 조건이 없으면 그대로 옮기지 말고, 사람에게 확인해서 `--eval`을 채운다.
