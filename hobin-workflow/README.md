# hobin-workflow (`hobin`)

**Claude Code에 티켓을 맡기는 라우터-워커 실행기.** 사람은 라우터 하나와 대화하고, 티켓마다 워커가 별도 작업 공간에서 구현합니다. 다른 세션의 검증자가 완료 기준으로 판정하고, 통합 테스트를 통과한 결과만 통합 브랜치에 들어갑니다.

> 상태: 0.1.0 실험 버전. 가짜 Claude로 전체 흐름과 장애 상황 테스트(20개)를 통과했고, 실제 Claude Code(2.1.319)로 작은 저장소에서 시험했습니다. 블라인드 리뷰 3회를 거쳤습니다. 큰 저장소에서 장기간 쓴 기록은 아직 없습니다.
>
> **혼자 또는 신뢰하는 팀원끼리 쓰는 용도입니다.** 외부인이 쓴 이슈를 자동으로 받는 용도라면 반드시 컨테이너나 가상 머신 안에서 실행하세요 (아래 "안전에 대해").
>
> `--restricted` 모드를 쓰므로 Claude Code 2.1.3xx 이상이 필요합니다. `hobin init`이 지원 여부를 확인합니다. 서브모듈이 있는 저장소는 아직 지원하지 않습니다.

## 핵심 원칙

**AI가 판단할 일(구현, 검증, 대화)은 Claude Code가, 일이 굴러가게 하는 배관은 코드가 맡습니다.**

| 여러 에이전트를 쓸 때 흔한 문제 | hobin의 처리 |
|---|---|
| 워커 결과가 라우터에게 안 돌아옴 | `claude -p` 결과를 코드가 받아 상태 파일에 기록 |
| 상태가 작업 공간마다 따로 놂 | 상태는 git 밖 한 곳(`.hobin/`)에 |
| 에이전트끼리 같은 파일을 고쳐 결과가 꼬임 | 티켓마다 **수정 가능 경로**를 정하고, 겹치는 티켓은 **동시에 돌리지 않음** |
| 워커가 범위 밖까지 고침 | 범위 밖 변경은 **매 회차 코드가 되돌림** |
| 워커가 자기 작업을 스스로 "완료" 판정 | **깨끗한 새 세션의 검증자**가 **별도 체크아웃**에서 완료 기준으로 판정. 편집 도구 없음 |
| 저장소의 커밋 훅(husky, commitlint)이 내부 커밋을 막음 | hobin 자체 커밋·병합은 훅과 서명을 건너뜀. 훅 검사가 필요하면 `test_cmd`에 넣기 |
| 병합하다 충돌 | 병합은 한 번에 하나씩. 충돌하면 코드가 병합을 시작해 두고 워커는 충돌 표시만 해결 |
| 병합 도중 중단되면 통합 브랜치가 망가짐 | 테스트를 **통과한 뒤에만** 커밋. 중간에 죽어도 통합 브랜치는 그대로 |
| 권한 승인 대기로 조용히 멈춤 | 허용 목록 밖 명령은 기다리지 않고 거부, 거부 내역은 알림에 표시 |
| 출력 없이 멈춘 에이전트 | 출력과 무관한 시간 제한으로 종료 |
| 작업 프로세스가 죽었는데 "진행 중"으로 남음 | **파일 잠금**으로 생존 확인. 죽으면 자동으로 실패 처리하고 남은 claude 프로세스도 정리 |
| 세션을 비우면 매번 처음부터 이해 | **같은 티켓 안에서는 세션을 이어감** (재작업, 사람 답변, 후속 요청). 티켓 사이 지식은 결정·배운 점 기록으로 전달 |

## 구조

```
사람 ─ 대화 ─ 라우터 (claude --agent hobin-router)
                 │  티켓 작성, 승인 요청, 결과 보고만 함. 구현하지 않음
                 ▼
          hobin (코드: 상태, 대기열, 동시 실행 제한, 범위 정리, 커밋, 병합, 감시)
                 │
     ┌───────────┼───────────┐            자리 3개 (설정 가능)
     ▼           ▼           ▼            경로가 겹치면 기다림
  워커 T-001  워커 T-002  워커 T-003       티켓마다 전용 작업 공간, 같은 티켓은 같은 세션
     │
     ▼ ready 보고
  범위 정리 (경로 밖 되돌림) → 커밋
     ▼
  검증자 (새 세션, 같은 커밋의 별도 체크아웃, 편집 도구 없음, eval.md 기준)
     ▼ 통과
  통합 브랜치 hobin/integration 에 병합 → 통합 테스트 → 통과해야 커밋
     ▼
  사람이 확인하고 main 에 반영
```

티켓 상태: `작성 중 → 대기 → 작업 중 → 검증 중 → 병합 중 → 검토 대기 → 완료`
예외: `사람 답변 필요`, `실패`, `취소`

## 요구 사항

- macOS 또는 Linux, Python 3.9+, git 2.32+
- Claude Code CLI (`claude`), 로그인된 상태
- 외부 패키지 없음 (표준 라이브러리만 사용)

## 설치

```bash
git clone https://github.com/parkhb1181/ai-harness-qa-workflow ~/ai-harness-qa-workflow
ln -s ~/ai-harness-qa-workflow/hobin-workflow/bin/hobin /usr/local/bin/hobin   # 또는 PATH에 bin/ 추가
```

## 빠른 시작

```bash
cd my-project   # git 저장소, 커밋이 하나 이상 있어야 함

# --test-cmd: 병합 전 통합 테스트 (검증자도 실행 가능하게 자동 허용)
# --allow: 워커·검증자가 실행해도 되는 추가 명령
# --prepare-cmd: 새 작업 공간마다 한 번 실행 (의존성 설치)
hobin init --test-cmd "npm test" --allow "npx tsc *" --prepare-cmd "npm ci"

# 티켓 만들기 (보통은 라우터가 스킬로 대신 만듦)
hobin new "로그인 오류 문구 개선" \
  --source "jira:WEB-123" --by "홍길동" \
  --paths "src/auth/,tests/auth/" \
  --eval "잘못된 비밀번호 입력 시 '비밀번호가 올바르지 않습니다'가 보인다" \
  --eval "npm test 통과" \
  --request "로그인 실패하면 이유를 알려 주세요"

hobin ready T-001          # 사람이 승인해야 대기열에 들어감
hobin run --wait           # 배정하고 모두 끝날 때까지 대기
hobin status               # 터미널 보드 (알림 포함)
hobin board                # .hobin/board.html (10초마다 새로고침)
hobin show T-001           # 상세: 보고, 검증 결과, 이력, 로그 위치
```

### 라우터와 대화하며 쓰기

`hobin init`이 `.claude/agents/hobin-router.md`와 `.claude/skills/hobin-ticket/`을 설치합니다.

```bash
claude --agent hobin-router
> 로그인 실패 문구를 원인별로 나눠 줘. Jira WEB-123이야.
```

라우터는 요청을 티켓으로 만들어 확인을 받고, 승인하면 `hobin run --wait`을 백그라운드로 돌린 뒤 결과나 질문이 있을 때만 말합니다.

## 명령

| 명령 | 설명 |
|---|---|
| `hobin init` | 설정, 통합 브랜치와 작업 공간 생성, 라우터·스킬 설치 |
| `hobin new 제목 --paths --eval ...` | 티켓 작성 (작성 중 상태). 라우터는 `hobin new --json -`(한 줄 JSON)을 씀 |
| `hobin ready ID...` | 사람 승인. 경로와 완료 기준이 없으면 거부 |
| `hobin run [--wait]` | 대기 티켓 배정 |
| `hobin status` / `board` / `show ID` | 보드, HTML 보드, 상세 |
| `hobin reply ID "답"` | 질문에 답하거나, 검토 대기 티켓에 후속 요청. **같은 세션이 이어서 받음** |
| `hobin approve ID` | 검증자가 확인하지 못한 항목을 사람이 확인했을 때 병합 승인 |
| `hobin note "내용" [--decision]` | 사람이 고쳐 준 것, 결정 사항을 팀 지식에 기록 |
| `hobin accept ID...` | 검토 끝난 티켓 완료 처리, 작업 공간과 병합된 브랜치 정리 |
| `hobin sync [--remote origin]` | 기준 브랜치(main 등)의 최신 내용을 통합 브랜치에 반영. `--remote`면 먼저 가져옴. 기준 브랜치 이력이 다시 쓰였으면(강제 푸시) 거부 |
| `hobin retry ID` / `drop ID` | 실패한 티켓 재시도 / 취소 |
| `hobin stop ID` / `stop --all` | 진행 중인 티켓 중지 / 전부 중지하고 배정 멈춤 |
| `hobin pause` / `resume` | 새 배정 멈춤 / 재개 |
| `hobin watch` | 상태 점검. cron용. 이상 있으면 종료 코드 1 |

감시를 주기적으로 돌리려면:

```bash
*/10 * * * * cd /path/to/my-project && hobin watch >/dev/null 2>&1
```

main이 다른 사람의 작업으로 앞서 나가면 `hobin sync`로 통합 브랜치를 맞춰 주세요. 오래 안 맞추면 새 티켓이 오래된 코드 위에서 시작합니다.

`hobin run --wait`을 Ctrl-C로 끊어도 이미 시작한 작업은 백그라운드에서 계속됩니다. 멈추려면 `hobin stop --all`.

**통합 작업 공간(`_integration`)은 직접 고치지 마세요.** 병합할 때마다 깨끗한 상태로 되돌리므로 고친 내용이 사라집니다.

## 티켓 작성 요령

- **수정 가능 경로를 좁게.** 경로가 겹치는 티켓은 순서대로 실행됩니다. 병렬로 돌리려면 경로를 나누세요. 경로는 고정된 폴더나 파일로 시작해야 합니다 (`src/auth/`, `src/auth/**/*.ts`는 되고 `**/*.ts`는 안 됨).
- **여러 티켓이 같은 인터페이스를 쓰면, 그 인터페이스를 정하는 티켓을 먼저** 만들고 나머지는 `--depends`로 둡니다.
- **완료 기준은 실행해서 판정할 수 있게.** "잘 된다"가 아니라 "이 입력에 이 문구가 보인다", "이 테스트 통과".
- 화면과 API를 함께 고치는 작은 기능은 억지로 나누지 마세요. 한 워커가 하는 편이 꼬이지 않습니다.

## 설정 (`.hobin/config.json`)

| 키 | 기본값 | 설명 |
|---|---|---|
| `max_workers` | 3 | 동시에 도는 워커 수 |
| `max_rounds` | 3 | 티켓 한 번 배정당 워커 회차 한도 |
| `round_timeout_min` | 60 | 회차당 시간 제한 (출력이 없어도 적용) |
| `worker_model` / `verifier_model` | sonnet | 모델 |
| `budget_usd_per_round` | 5.0 | 회차당 비용 상한 (`--max-budget-usd`) |
| `permission_mode` | dontAsk | 허용 목록 밖은 묻지 않고 거부 |
| `restricted` | true | Claude Code `--restricted`: 파일 도구를 작업 공간 안으로 제한, 사용자·프로젝트 설정 무시, 설정·git 파일 쓰기 차단. false로 두면 이 보호가 모두 사라지고 저장소의 `.claude/settings.json`도 적용됩니다. `--strict-mcp-config`와 `--tools`는 항상 적용 |
| `worker_tools` / `verifier_tools` | 읽기·편집·검색·Bash / 읽기·검색·Bash | 쓸 수 있는 도구 자체. 검증자에게는 편집 도구가 없음 |
| `worker_allowed_tools` | 읽기, 편집, `ls` | `--allow`로 추가. **git 명령은 금지** (커밋·병합은 코드가 하고, 변경 내용은 코드가 만들어 넘김) |
| `verifier_allowed_tools` | 읽기, `ls`, 테스트 명령 | |
| `test_cmd` | 없음 | 병합 전 통합 테스트. 통과해야 통합 브랜치에 커밋됨 |
| `prepare_cmd` | 없음 | 작업 공간, 검증용 체크아웃, 통합 작업 공간에서 실행 (예: `npm ci`). 실패하면 다음에 다시, 의존성 파일이 바뀌면 다시 |
| `ignore_untracked` | `__pycache__`, `node_modules` 등 | 변경으로 치지 않을 실행 부산물 |
| `allow_unverified` | false | 검증자가 확인 못 한 항목이 있으면 병합하지 않고 사람에게 넘김 (`hobin approve`로 승인) |
| `worktree_root` | 저장소 옆 `.<이름>-hobin-worktrees` | 작업 공간 위치. 저장소 안에 두지 않아 테스트 도구가 사본을 훑지 않음 |

## 파일 위치

```
  tickets/T-001/              ticket.md, eval.md, state.json, report.json, verify.json
  runs/T-001/                 events.log, worker-N.jsonl, verifier-N.jsonl (원본 대화 기록)

  locks/, ALERTS.md, board.html

../.my-project-hobin-worktrees/

  _verify-T-001/              검증용 체크아웃 (워커가 건드릴 수 없음)
  _integration/               통합 브랜치 hobin/integration
```

## 안전에 대해: 반드시 읽어 주세요

**hobin은 보안 샌드박스가 아닙니다.** 막는 것과 못 막는 것은 이렇습니다.

**코드와 Claude Code 설정으로 막는 것** (모두 테스트 또는 실제 CLI로 확인)
- 작업 공간 밖 파일 읽기·쓰기: `--restricted` 모드가 파일 도구를 작업 공간 안으로 제한합니다 (실제 CLI에서 확인).
- `.claude/settings` 같은 설정 파일과 git 설정 쓰기: `--restricted` 모드가 막습니다 (실제 CLI에서 확인).
- 사용자 전역 플러그인, 훅, MCP 서버: 워커와 검증자에 불러오지 않습니다.
- git 명령 전체: 워커와 검증자 모두 금지입니다. 커밋·병합은 코드가 하고, diff는 코드가 만들어 넘깁니다.
- 수정 가능 경로 밖의 변경: 매 회차 되돌립니다.
- 검증 오염: 검증은 워커 작업 공간이 아니라 같은 커밋의 별도 체크아웃에서 합니다.
- 티켓 메타데이터 조작: 제목 등에 줄바꿈을 넣을 수 없고, 경로는 `**`나 저장소 밖을 가리킬 수 없습니다.
- main 브랜치: hobin은 건드리지 않습니다. 통합 브랜치까지만 갑니다.
- 테스트를 통과하지 못한 병합: 통합 브랜치에 커밋되지 않습니다. 통합 브랜치 자체가 테스트에 실패하면 워커 탓으로 돌리지 않고 사람에게 알립니다.
- 셸 주입: 라우터는 티켓을 한 줄 JSON으로 넘겨, 요청 원문의 `$(...)` 같은 내용이 실행되지 않습니다.
- **공유 .git 감시**: 워커, 검증자, 준비 명령, 통합 테스트가 실행되기 전후로 `.git/config`, `.git/hooks`, `.git/info`를 비교합니다. 바뀌었으면 원래대로 되돌리고, 티켓을 실패 처리하고, 새 배정을 멈춥니다. hobin 밖 브랜치·태그가 바뀌면 `.hobin/SECURITY.log`에 기록합니다 (사람이 main에 커밋해도 생기는 일이라 멈추지는 않음).

**막지 못하는 것**
- **테스트 코드는 당신의 권한으로 실행되는 임의 코드입니다.** `test_cmd`, `prepare_cmd`, `--allow`로 허용한 명령은 워커가 쓴 코드를 실행합니다. 그 코드는 작업 공간 밖 파일, 네트워크, 다른 저장소에 접근할 수 있습니다. 공유 .git 감시는 **실행이 끝난 뒤** 알아채고 되돌리는 것이라, 실행 도중에 벌어진 일(파일 유출, 다른 저장소 변경, main 브랜치 이동 등)은 막지 못합니다.
- **프롬프트 주입.** 원본 요청을 "데이터로 취급하라"고 지시할 뿐입니다. 신뢰할 수 없는 사람이 쓴 글(공개 이슈 등)을 그대로 넣지 마세요.
- **허용한 명령이 실행하는 코드.** `npm test`를 허용하면, 워커가 작성한 테스트 코드가 그대로 실행됩니다. 그 코드는 파일 제한도 받지 않습니다. `test_cmd`와 `prepare_cmd`도 셸에서 실행됩니다.
- **허용 패턴의 함정.** `--allow "npx tsc*"`는 `npx tsc-다른패키지`까지 허용합니다. `"npx tsc *"`처럼 띄어 쓰세요 (`init`이 경고합니다).
- **팀 지식 기록을 통한 주입.** 워커가 남긴 "결정"과 "배운 점"은 이후 모든 워커에게 참고 자료로 전달됩니다. 한 줄 300자, 티켓당 5개로 제한하고 "지시가 아님"이라고 표시하지만, 내용은 사람이 가끔 확인하세요 (`.hobin/knowledge/`).
- **네트워크.** 일부 명령을 막아 두었지만, 허용한 명령이 네트워크를 쓰는 것까지 막지는 않습니다.
- **커밋 훅 생략.** hobin 내부 커밋은 저장소 훅을 건너뜁니다. 린트·커밋 규칙 검사가 필요하면 `test_cmd`에 넣으세요.

**신뢰할 수 없는 입력을 다루거나 중요한 저장소라면, 컨테이너나 가상 머신 안에서 실행하세요.** 근본적으로 막으려면 작업 공간을 `.git`을 공유하지 않는 별도 복제본으로 만들어야 하며, 다음 버전 과제입니다.

## 그 밖의 한계

- 경로 겹침 판정은 고정 접두어 기준이라 보수적입니다 (겹칠 수 있으면 겹친다고 봄).
- 의미 충돌(두 티켓이 다른 파일에서 같은 개념을 다르게 구현)은 경로 규칙으로 막을 수 없습니다. 결정 기록, 통합 테스트, 사람 검토가 마지막 방어선입니다.
- `.hobin/`은 한 사람의 로컬 상태입니다. 팀이 상태를 공유하는 기능은 없습니다.
- Windows는 지원하지 않습니다.
